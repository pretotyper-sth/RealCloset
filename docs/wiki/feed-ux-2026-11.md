# 피드 UI·문구 수정 내역 — 2026-11-01

## UI 수정

- 아이템 가로 목록: 자동 스냅을 제거해 스크롤한 지점에 정지. 카드는 후속 요청에 따라 모두 212px 고정 폭으로 맞추고, 간격은 12px → 8px. 상품명 길이에 따라 폭이 달라지지 않는다. 기존 전체 아이템 목록 바텀시트 연결 유지.
- 꾸미기 패널: 스티커·펜·이미지 등 제목 왼쪽 정렬. 텍스트 패널에도 같은 제목 추가. 모바일 텍스트 패널도 다른 도구와 같은 공통 높이를 사용하고 16개 색상을 두 줄로 표시.
- 요소 순서 버튼: 뒤로·앞으로·복제·삭제를 모두 테두리·타원·그림자 없는 36px 높이/11px 글자/6px 8px 안쪽 여백의 텍스트 버튼으로 통일. 비활성 상태와 실제 레이어 순서 동작 유지.
- 내 피드: 모바일에서 전체 제목·카드 시작·오른쪽 아이콘 끝을 화면 양옆 16px에 정렬.

## 검증

- 격리된 로컬 화면에서 390×844 모바일 및 1280×900 PC 확인. 실제 사용자 계정/유료 API 호출 없이 테스트용 응답만 사용.
- 모바일 가로 목록 scrollLeft=19.5px에서 정지(최대 46px), scroll-snap-type=none, 간격 8px. 아이템 클릭 시 기존 3개 전체 목록 열림.
- 모바일 내 피드 제목/카드 left=16px, 마지막 아이콘 right=374px(390px 화면), 페이지 가로 넘침 없음.
- 스티커/펜/이미지/텍스트 제목과 36px 버튼 확인. 레이어 순서·피드 빈 상태 테스트 6개 통과.
- 백엔드 AST 비교에서 문자열 이외의 로직 차이 없음. 백엔드 전체 피드 테스트는 로컬 FastAPI 의존성 미설치로 실행하지 못함.
- 변경 JSX lint 오류 없음(기존 hook/순수성 경고 유지). 빌드 결과와 배포 여부는 작업 로그 참고.

## 후속 문구 검토

사용자 요청으로 탐색 안내 ‘저장하고 내 옷으로 리스타일해 보세요.’를 복원한다. 재구성 허용은 `model.js` newLook의 allowRemix=true 및 canRemix 판단과 서버 필드만 있으며 현재 편집기/게시/공유 화면에 토글이 없다. 공유창에서 사용자가 바꿀 수 있는 것은 공개 범위이다. 따라서 작성자가 허용 여부를 설정하는 UI가 있는 것처럼 안내하지 않는다. 기존 저장값/판단은 이 문구 작업에서 변경하지 않는다. 후속 확인 결과 재구성 아이콘의 접근성 이름/툴팁과 공유 상세 버튼은 모두 ‘내 스타일로 재구성하기’로 통일했다. 공유 페이지 소개도 ‘공유된 피드를 내 스타일로 재구성해 보세요.’로 맞췄다. 설정 UI가 있다는 오해를 피하기 위해 기존 재구성 불가 안내는 ‘이 피드는 재구성할 수 없어요.’로 정리했다. 코디 CTA ‘이 코디로 피드 만들기’는 유지한다.

최종 후속 문구: 탐색 안내 원문 유지 / 재구성 액션 전체 ‘내 스타일로 재구성하기’ / 코디 CTA ‘이 코디로 피드 만들기’. 이전 36개 비교 목록은 최초 수정 이력이며 위 후속 문구가 현재 기준이다.

## 공개 옷·편집기·공통 레이아웃 후속 개선

- 피드 아이템은 고정 폭212px/간격8px, 자동 스냅 없음. 상품명·브랜드는 기존 한 줄 말줄임.
- 텍스트 패널만의 높이 override를 제거해 다른 도구와 기본 높이 및 손잡이 크기 조절 기준을 공유한다. 텍스트 전용 팔레트16개/8열 두 줄, 기존 펜 색상은 유지한다.
- 이미 캔버스에서 직접 입력하는 텍스트의 중복 수정(연필) 버튼을 제거. 도구 행은 nowrap, 좁은320px에서도 같은 줄을 유지하며 필요한 경우 도구 행 안에서 가로 스크롤한다.
- CreatorProfile 공유 카드에서 제목 두 줄 높이를 예약하고 말줄임, 카테고리는 한 줄로 제한해 본인·타인의 공개 옷 정보를 정렬. 본인 공개 버튼도 동일 행 높이에 배치한다.
- 공개 버튼은 즉시 목표 상태로 반영하고 아이템별 중복 요청을 차단한다. 기존 PATCH→공개 옷 저장→프로필 저장→공개 옷 중복 저장(쓰기4회)을 PATCH→공개 옷 저장(2회)으로 줄였다. 실패하면 기존 상태로 되돌리며, 일부 저장/응답 실패 때 두 저장소의 이전 상태 복구를 시도한다. 복구도 실패하면 새로고침 안내를 표시해 저장 성공으로 오인하지 않게 한다.
- `profile-visibility.js`는 다른 옷의 동시 상태를 보존하는 visibleItems와 저장/실패 복구를 관리한다. `09-app.jsx` setItemVisibility는 옷장 저장·로컬 캐시만 담당하고, CreatorProfile이 공개 옷 저장을 한 번 수행한다. ConnectionsPage에도 같은 콜백을 전달한다.
- 날짜와 날씨는 `.lb-context-strip` 한 가로 스크롤 안에 위치한다. 달력은 그 바깥에 유지하고 화면 경계에 맞게 위치를 보정한다.
- 피드 배경은 var(--ivory), 제목은 모바일20px/800·좌18px/상22px, PC25px/800·좌32px/상28px(큰 화면 좌40/56px). 기존 피드 아이콘과 탐색/저장 기능은 유지한다.

검증: 관련 JS 테스트13개(공개 상태 성공/실패/복구 실패/동시 다른 옷 보존 포함) 통과. 390×844에서 스티커·텍스트 패널 높이337.59px 동일, 색상16개 두 행, 텍스트 수정 버튼0개, 도구 버튼 같은 y좌표. 320px에서도 도구 행만 가로 스크롤하고 페이지 가로 넘침 없음. 1.5초 지연된 모의 저장 응답 전 ‘공개 중’ 표시, 실패 시 ‘공개하기’ 복구 및 두 저장소 복구 요청 확인. 실제 사용자 옷 공개 상태는 검증 목적으로 바꾸지 않았다. 본인/타인 모바일 제목33px 두 줄·같은 행 버튼y좌표 일치, PC 제목36px와 버튼 정렬 확인. 날짜 스크롤 후 dateLeft20→-12px와 달력 열림 확인. 피드 배경색/제목 크기/위치 및 고정 아이템 폭212px 확인. 수정 모듈 lint 오류 없음(기존 경고 유지).
